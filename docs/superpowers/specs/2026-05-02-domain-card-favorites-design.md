# 领域卡收藏功能设计

## 背景

当前领域卡选择使用通用卡牌选择弹窗：

- 主入口在 `components/modals/card-selection-modal.tsx`
- 左侧类型栏在 `components/modals/card-selection/CardTypeSidebar.tsx`
- 卡片网格由 `CardGrid` / `InfiniteCardGrid` 渲染

现状问题：

1. 领域卡数量较多时，重复选择常用领域卡效率偏低。
2. 当前左侧类型栏只能在标准卡牌类型之间切换，无法提供“我常用的那几张领域卡”快速入口。
3. 角色维度下不存在领域卡偏好记录，切换角色后无法保留各自常用领域卡集合。

目标是补上一条最小但完整的领域卡收藏链路：

- 在领域卡选择弹窗内，为每张领域卡提供右上角五角星收藏按钮。
- 在左侧类型栏中增加一个 `收藏` 入口。
- 收藏按角色保存，而不是全局共享。

## 目标

实现一个仅作用于领域卡选择场景的收藏能力，使用户可以为当前角色维护一组常用领域卡，并在弹窗里通过左侧 `收藏` 分组快速查看和选择。

## 非目标

以下内容不在本期范围：

1. 不扩展到职业、种族、社群、子职业等其他卡牌类型。
2. 不在顶部“类别”筛选器里增加 `收藏` 选项。
3. 不做全局收藏。
4. 不做排序、批量收藏、收藏数量统计。
5. 不改变现有卡牌选择、筛选和批次过滤的基本行为。

## 用户故事

### 用户故事 1：在领域卡上直接收藏

作为用户，我希望在领域卡选择弹窗里直接点击卡片右上角的五角星，把当前领域卡加入或移出我的收藏列表，而不用借助额外页面。

### 用户故事 2：按角色保留收藏列表

作为拥有多个角色的用户，我希望不同角色可以维护各自的领域卡收藏集合。切换角色后，收藏内容应该跟着角色变化。

### 用户故事 3：通过左侧入口快速只看收藏

作为用户，我希望在左侧类型栏中点击 `收藏`，只查看当前角色已收藏的领域卡，以便快速选卡。

## 当前实现分析

### 领域卡选择弹窗入口

`components/modals/card-selection-modal.tsx`

该组件负责：

1. 维护当前 `activeTab`
2. 调用 `useCardFiltering()` 生成筛选后的卡牌列表
3. 将卡牌数据交给 `InfiniteCardGrid` 渲染
4. 通过左侧 `CardTypeSidebar` 切换卡牌类型

当前它没有“伪分组”概念，左侧切换值默认都是真实卡牌类型。

### 左侧类型栏

`components/modals/card-selection/CardTypeSidebar.tsx`

当前它只展示：

- 标准卡牌分组
- 扩展卡牌分组

其中标准卡牌默认顺序为：

1. 领域
2. 职业
3. 子职业
4. 种族
5. 社群

当前没有领域专属额外入口。

### 卡片渲染层

`components/modals/display/CardGrid.tsx`

该层会根据模式渲染：

- 图片卡：`ImageCard`
- 文本卡：`SelectableCard`

当前卡片组件只负责点击选卡，不包含收藏按钮，也没有向外暴露卡片角标操作插槽。

### 角色数据存储

当前角色主数据结构定义在：

- `lib/sheet-data.ts`

角色默认值与兼容链路在：

- `lib/default-sheet-data.ts`
- `lib/sheet-data-migration.ts`
- `lib/character-data-validator.ts`

这意味着只要收藏按角色保存，就必须把收藏字段并入 `SheetData`，并同步打通默认值、迁移和校验链路。

## 设计原则

### 1. 只在领域卡场景启用

收藏入口和收藏分组只在领域卡选择相关上下文中出现。

理由：

1. 这是用户明确要求的范围。
2. 当前需求不需要抽象成全卡牌收藏系统。
3. 这样可以把改动控制在最小范围，降低主弹窗回归风险。

### 2. 收藏数据按角色保存

收藏列表直接并入 `SheetData`。

理由：

1. 当前角色切换已经以 `SheetData` 为中心。
2. 这样不需要额外引入新的 localStorage 命名空间。
3. 多角色切换、导入导出和迁移链路可以沿用现有模型。

### 3. 收藏分组是“领域视图的伪分组”，不是新卡牌类型

左侧 `收藏` 不应被建模成新的 `CardType`。

理由：

1. `收藏` 本质上是领域卡的一个筛选视图，而不是新的业务卡牌类型。
2. 避免污染 `card/card-types.ts` 的类型体系。
3. 可在弹窗层用最小条件分支处理。

### 4. 收藏按钮不能干扰选卡行为

五角星按钮必须是卡片上的独立交互热点。

要求：

1. 点击星标时不触发卡牌选择。
2. 点击卡面其它区域时保持原有选卡行为。
3. 文本模式和图片模式都要支持收藏按钮。

## 最终方案

### 数据模型

在 `SheetData` 中新增字段：

- `favoriteDomainCardIds: string[]`

语义：

- 保存当前角色收藏的领域卡 ID 列表。

默认值：

- 空数组 `[]`

需要同步的位置：

1. `lib/sheet-data.ts`
2. `lib/default-sheet-data.ts`
3. `lib/sheet-data-migration.ts`
4. `lib/character-data-validator.ts`
5. HTML 导入导出链路

### Store 能力

在 `lib/sheet-store.ts` 增加领域卡收藏相关 action，建议至少包含：

1. `toggleFavoriteDomainCard(cardId: string)`
2. `isFavoriteDomainCard(cardId: string)`

行为要求：

1. 若卡牌 ID 已存在，则移除。
2. 若卡牌 ID 不存在，则加入。
3. 只允许操作非空的领域卡 ID。
4. 去重由 store 保证，不允许同一 ID 重复写入。

### 左侧类型栏新增 `收藏`

修改：

- `components/modals/card-selection/CardTypeSidebar.tsx`

行为：

1. 保持现有标准卡牌顺序不变。
2. 仅在当前弹窗处于领域卡上下文时，额外显示一个 `收藏` 入口。
3. `收藏` 入口与 `领域` 同级显示在左侧标准卡牌分组中。

这里的“领域卡上下文”定义为：

- 当前 `CardSelectionModal` 正在服务于领域卡选择流程。

不要求在职业、种族、社群等非领域场景显示该入口。

### 弹窗视图切换逻辑

修改：

- `components/modals/card-selection-modal.tsx`

设计：

在弹窗层引入一个轻量视图值：

- `domain`
- `favorites`
- 其他原有卡牌类型

行为：

1. 当左侧点击 `领域` 时，保持现有领域卡列表逻辑。
2. 当左侧点击 `收藏` 时，只显示当前角色 `favoriteDomainCardIds` 对应的领域卡。
3. `收藏` 视图下仍保留顶部卡包、类别、等级、搜索筛选能力。
4. `收藏` 视图的筛选基底是“当前角色已收藏的领域卡集合”，再叠加现有筛选条件。

### 卡片右上角五角星按钮

修改：

- `components/modals/display/CardGrid.tsx`
- `components/modals/display/InfiniteCardGrid.tsx`
- `components/ui/image-card.tsx`
- `components/ui/selectable-card.tsx`

建议做法：

1. 在 `CardGrid` 层新增可选收藏相关参数。
2. 将这些参数透传到图片卡和文本卡组件。
3. 仅当满足以下条件时显示星标：
   - 当前卡是领域卡
   - 当前弹窗允许收藏交互

按钮表现：

1. 未收藏：空心星
2. 已收藏：高亮星
3. 点击后立即切换视觉状态

事件要求：

1. `stopPropagation()`，避免触发选卡。
2. 不影响 hover、预览和无限滚动。

### 空状态

当用户进入左侧 `收藏` 分组且当前角色没有任何收藏领域卡时：

- 内容区显示空状态文案，例如：`还没有收藏的领域卡`

这应复用现有 `ContentStates` 空状态能力，不额外引入新空状态组件。

## UI 行为

### 普通领域卡视图

1. 左侧选中 `领域`
2. 显示全部领域卡
3. 每张领域卡右上角可点五角星

### 收藏视图

1. 左侧选中 `收藏`
2. 仅显示当前角色已收藏的领域卡
3. 卡片仍然可点击选中
4. 点击五角星可以取消收藏；若因此不再满足收藏条件，卡片应从当前结果集中移除

### 角色切换

当用户切换角色后：

1. 收藏列表跟随新角色变化
2. 再次打开领域卡弹窗时，应反映该角色自己的收藏状态

## 数据兼容与迁移

### 新字段迁移

对历史角色数据：

- 若不存在 `favoriteDomainCardIds`
- 迁移后补为 `[]`

### 导入导出影响

由于收藏按角色保存并且挂在 `SheetData` 下，以下链路都应保留该字段：

1. 多角色 localStorage 存档
2. HTML 导出
3. HTML 导入
4. 通用角色数据验证与清洗

## 风险

### 风险 1：把 `收藏` 当成真实卡牌类型

如果把 `收藏` 做成新的 `CardType`，会污染通用卡牌类型体系，并影响现有筛选和显示逻辑。

规避方式：

- 只在弹窗层作为领域视图的伪分组处理。

### 风险 2：星标点击误触发选卡

如果事件没拦住，用户点击收藏会直接选中卡牌并关闭弹窗。

规避方式：

- 星标点击必须显式阻止事件冒泡。

### 风险 3：角色切换后收藏状态错乱

如果收藏状态挂在全局 UI store 而不是 `SheetData`，切换角色后会出现收藏串号。

规避方式：

- 收藏字段只保存在当前角色数据中。

### 风险 4：收藏视图与现有筛选叠加后出现空结果误判

用户可能已经有收藏，但因为顶部筛选条件仍然生效而看不到结果。

规避方式：

- 维持现有筛选语义，但空状态文案要清楚表示“未找到符合条件的卡牌”。

## 验证计划

### 手工验证 1：基础收藏切换

1. 打开领域卡选择弹窗。
2. 对任意领域卡点击星标。
3. 确认卡牌未被选中、弹窗未关闭。
4. 确认星标状态立即变化。

### 手工验证 2：收藏视图筛选

1. 收藏 2 到 3 张领域卡。
2. 点击左侧 `收藏`。
3. 确认只显示已收藏的领域卡。
4. 在收藏视图里取消其中一张收藏。
5. 确认该卡从当前结果集中移除。

### 手工验证 3：按角色隔离

1. 角色 A 收藏若干领域卡。
2. 切换到角色 B。
3. 打开领域卡弹窗，确认不会看到角色 A 的收藏状态。
4. 切回角色 A，确认原收藏仍在。

### 手工验证 4：兼容性

1. 使用旧角色数据打开页面。
2. 确认不会因缺少 `favoriteDomainCardIds` 报错。
3. 导出并重新导入角色数据后，确认收藏字段仍保留。

## 实现边界总结

本期目标是：

- 让领域卡可以被当前角色收藏
- 让收藏可在领域卡弹窗里快速访问

本期刻意不做：

- 全卡牌收藏系统
- 收藏排序
- 收藏统计
- 额外管理页面

这是一次面向当前需求的最小正确实现，而不是对整个卡牌选择体系的泛化重构。
